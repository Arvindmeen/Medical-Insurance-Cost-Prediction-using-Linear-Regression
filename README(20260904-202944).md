# Insurance Charges Prediction --- Linear Regression From Scratch

A machine learning project that predicts individual medical insurance
charges using **Linear Regression implemented from scratch with NumPy**,
including feature engineering, normalization, model evaluation,
cross-validation, coefficient analysis, residual diagnostics, and Ridge
Regression comparison.

## Project Overview

This project uses an insurance dataset containing demographic,
lifestyle, and regional information to predict the `charges` paid by an
individual.

The notebook follows a complete machine-learning workflow:

1.  Load and inspect the dataset
2.  Check dataset dimensions and missing values
3.  Encode categorical variables
4.  Separate features and target
5.  Perform feature engineering
6.  Normalize features
7.  Add an intercept term
8.  Split data into training and testing sets
9.  Train Linear Regression from scratch using the Normal Equation
10. Evaluate the model using R² and RMSE
11. Analyze feature coefficients
12. Visualize actual vs. predicted charges
13. Perform 5-fold cross-validation
14. Analyze residuals
15. Compare with Ridge Regression

## 3. Categorical Encoding

The `sex` and `smoker` columns are converted from categorical values
into binary numerical values.

### Sex

``` python
data["sex"] = data["sex"].map({
    "female": 0,
    "male": 1
})
```

### Smoker

``` python
data["smoker"] = data["smoker"].map({
    "no": 0,
    "yes": 1
})
```

The resulting representation is:

``` text
female → 0
male   → 1

no     → 0
yes    → 1
```

## 4. One-Hot Encoding of Region

The `region` feature contains four categories, so one-hot encoding is
applied:

``` python
data = pd.get_dummies(
    data,
    columns=["region"],
    drop_first=True,
    dtype=int
)
```

With `drop_first=True`, three region indicator columns are created:

``` text
region_northwest
region_southeast
region_southwest
```

The omitted region becomes the reference category.

After encoding, the dataset contains **9 columns**.

## 5. Feature and Target Separation

The target variable is `charges`.

``` python
X = data.drop("charges", axis=1)
y = data["charges"]
```

Therefore:

``` text
X → input features
y → insurance charges
```

## 6. Feature Engineering

Additional features are created to capture nonlinear effects and
interactions between variables.

### Smoker × BMI Interaction

``` python
X_engineered["smoker_bmi"] = (
    X_engineered["smoker"] * X_engineered["bmi"]
)
```

This allows the model to represent an interaction between smoking status
and BMI.

### Smoker × Age Interaction

``` python
X_engineered["smoker_age"] = (
    X_engineered["smoker"] * X_engineered["age"]
)
```

### Age Squared

``` python
X_engineered["age_sq"] = X_engineered["age"] ** 2
```

### BMI Squared

``` python
X_engineered["bmi_sq"] = X_engineered["bmi"] ** 2
```

The engineered feature set therefore contains:

``` text
Original numerical/binary features
+ smoker_bmi
+ smoker_age
+ age_sq
+ bmi_sq
```

The resulting design matrix, after adding the intercept, has shape:

``` text
(1338, 13)
```

## 7. Feature Normalization

The engineered features are standardized using their mean and standard
deviation:

``` python
mean = X_engineered.mean()
std = X_engineered.std()

X_normalized = (X_engineered - mean) / std
```

This transforms the features to a common scale.

An intercept column of ones is then added:

``` python
X_final = np.c_[
    np.ones(X_normalized.shape[0]),
    X_normalized.to_numpy()
]
```

The target is converted into a column vector:

``` python
y_final = y.to_numpy().reshape(-1, 1)
```

## 8. Train-Test Split

A reproducible random split is performed using NumPy:

``` python
np.random.seed(42)

indices = np.random.permutation(len(X_final))
test_size = int(len(X_final) * 0.2)

test_idx, train_idx = (
    indices[:test_size],
    indices[test_size:]
)
```

Approximately:

``` text
80% → Training data
20% → Testing data
```

## 9. Linear Regression From Scratch

Instead of using a machine-learning library's Linear Regression
implementation, the model parameters are calculated directly using the
**Normal Equation**.

The implementation is:

``` python
theta = (
    np.linalg.pinv(X_train.T @ X_train)
    @ X_train.T
    @ y_train
)
```

The pseudoinverse is used through:

``` python
np.linalg.pinv()
```

This produces the model parameter vector `theta`.

Predictions are generated using:

``` python
y_pred_train = X_train @ theta
y_pred_test = X_test @ theta
```

This demonstrates how Linear Regression can be implemented without
directly relying on a high-level ML estimator.

## 10. Model Evaluation

Two evaluation metrics are calculated:

### R² Score

The notebook calculates R² manually:

``` python
r2 = 1 - (
    np.sum((y_actual - y_predicted) ** 2)
    /
    np.sum((y_actual - np.mean(y_actual)) ** 2)
)
```

### RMSE

The test RMSE is calculated as:

``` python
rmse_test = np.sqrt(
    np.mean((y_test - y_pred_test) ** 2)
)
```

## Results

The implemented Linear Regression model achieved:

  Metric                Result
  -------------- -------------
  Training R²       **0.8380**
  Testing R²        **0.8693**

The test R² of **0.8693** means that the model explains approximately
**86.93% of the variance in insurance charges on the test set**.

## 15. Ridge Regression Comparison

The notebook also implements Ridge Regression manually.

A regularization parameter is selected:

``` python
lambda_param = 1.0
```

The identity matrix is created and the intercept is excluded from
regularization:

``` python
I = np.identity(X_train.shape[1])
I[0, 0] = 0
```

The Ridge solution is then calculated:

``` python
theta_ridge = (
    np.linalg.inv(
        X_train.T @ X_train
        + lambda_param * I
    )
    @ X_train.T
    @ y_train
)
```

The resulting test R² is:

``` text
Ridge Regression (λ=1.0) Test R²: 0.8695
```

### Model Comparison

  Model                             Test R²
  ---------------------------- ------------
  Linear Regression              **0.8693**
  Ridge Regression (λ = 1.0)     **0.8695**

Ridge Regression gives a very small improvement over the ordinary Linear
Regression result for this particular split and regularization value.

## Limitations

This repository documents the methodology and results present in the
notebook. The current implementation has several areas that could be
improved in a production-quality ML pipeline:

-   The preprocessing statistics are calculated before the train-test
    split, so a production implementation should fit preprocessing
    parameters using training data only.
-   The same engineered features are used for all evaluation steps.
-   The Ridge regularization parameter is fixed at `λ = 1.0`; systematic
    hyperparameter tuning could be added.
-   The notebook focuses on Linear/Ridge Regression rather than
    comparing a wider range of regression algorithms.
-   The dataset is relatively small, so performance should not be
    interpreted as evidence of generalization to all insurance
    populations.
